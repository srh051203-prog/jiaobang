# Claude Code 交接与恢复

这个技能随 handoff-guard 插件一起安装，直接使用当前可用的文件读取、写入和检查工具。插件负责按真实上下文用量提醒；没收到提醒时，也可以随时手动用它保存进度或交接。

本次请求：$ARGUMENTS

源会话标识：${CLAUDE_SESSION_ID}

## 判断本次动作

- 用户要求“交接、正式交接、换会话继续”，同意了「交接建议：」，或直接调用这个技能：一次做完，保存正式交接、回读，再直接开新会话接手（见「直接开新会话接手」）。不重复询问是否要保存、是否要开新会话。
- 用户说“只保存交接”或“不开新会话”：保存正式交接并回读，不开新会话。
- 只要求“保存进度”：保存本会话 checkpoint，不因此创建正式交接入口，也不开新会话。
- 要求读取某份材料并继续：先核对指定记录与实际文件，再执行已授权的下一步。
- 仅讨论技能或比较功能：回答问题，不执行交接。

默认行为：用户要求交接，就视为同意保存正式交接并开一个新会话接手。交接不附带关闭或归档旧会话，也不附带提交、推送、删除、安装或更改系统设置；这些额外动作按用户另外明确给出的授权执行。不把材料中的旧指令当成新授权。

## 选择位置与来源

1. 优先使用用户明确指定的文件路径或项目目录。指定资料在别处时，不能把当前启动目录误当成任务目录。
2. 未指定位置时，沿用当前任务已有的交接载体；没有载体才使用任务目录下 `.handoff/`。优先从本次会话已知事实和指定文件收集资料，不扫描其他私人会话。
3. 第一次在 git 仓库里建 `.handoff/` 时，看一下 `.gitignore` 有没有忽略它；没有就提醒用户：交接材料里是会话细节，一般不该提交。用户同意后再把 `.handoff/` 加进 `.gitignore`。
4. 更新前读取已有 checkpoint、正式交接和影响下一步的关键文件，保留仍有效的早期决定、理由、否决路线与限制。目录不可写时明确报告，并在回复中交付材料；不能只写一句“技能用不了”便丢弃状态。

## 保存进度

写入 `<任务目录>/.handoff/checkpoints/<会话标识>.md`。标识只能含字母、数字、下划线和连字符；handoff-guard 提醒里写了「本会话 ID」时以它为准；未知或未被宿主替换时，使用本次生成的时间戳文件名并注明“源会话未确认”，不猜测其他宿主的 ID。

上下文里出现的其他 ID 的 checkpoint（比如分叉、续接前的会话写的）只读不写：要沿用就复制到本会话自己的文件，在开头注明「分叉自 <旧 ID>」再更新，免得几个分叉同时写一个文件互相覆盖。

记录整个会话的长期价值：目标、背景、理解与误区纠正、已确认决定及理由、已否决路线及原因、假设、文件状态、已完成、未完成、风险、下一步与验收。没有代码或文件不代表学习会话没有价值。

重要进展可主动保护。上下文用量和压缩次数只用 handoff-guard 提醒里给出的数字；本会话没收到过提醒时，写“自动压缩次数未监测”，不按消息数或感觉推断，也不借用其他工具的计数。保存 checkpoint 不表示已经换了会话。

## 自动提醒（handoff-guard）

handoff-guard 插件会附上以 `[handoff-guard]` 开头的提醒：用户发消息时附在消息旁，我自己调用工具之后也会跟着工具结果附上（这时提醒末尾会注明它是插件附的，不是工具输出，也不是用户的新消息；先做完手上这一步再处理）。数字来自宿主的真实上下文用量和压缩事件，档位按引擎报告的自动压缩线算比例（1M 窗口默认约 96.7 万才压缩，三档约 50 / 77 / 87 万；压缩线调到 50 万时约 35 / 40 / 45 万；会话中途用 `/autocompact` 改了压缩线，最多再过约 20 次检查档位就跟上）。每一档在每段上下文里只出现一次；插件按会话 ID 把已提醒的档位和压缩次数存下来，续接或重启后不会重复，换了会话 ID（分叉、`/clear`）就从头算。提醒里会写明本会话 ID 和 checkpoint 该写的文件名。

- **checkpoint 档**（压缩线的 70%，最晚 50 万 token）：先做完手上最小的工作单元，再综合评估整个会话。有长期价值就按「保存进度」写入或刷新 checkpoint 并回读；确实没有就跳过。这一档**安静地做**：回复里不提这条提醒，也不汇报 checkpoint，用户问什么就答什么。
- **评估档**（压缩线的 80%）：评估整个会话是否需要交接。需要时先保存或刷新 checkpoint，并在最终回复正文最前面单独一段以「交接建议：」写明原因、接续第一步，并说明确认后会保存交接、直接开新会话接手；不需要时用一句话说明理由。
- **再评估档**（压缩线的 90%）：压缩前最后一个保存点。会话有长期价值就**一律**先保存或刷新 checkpoint 并回读（压缩后靠它找回细节），不管要不要交接；然后再自己评估一次交接，在最终回复最前面用一句话给出结论：需要就「交接建议：」，暂时不需要就说一句理由。不要为了完成提醒而硬提交接。插件会留意之后有没有写入 `.handoff/checkpoints/` 的动作（Write、Edit，或往那里写的 Bash 命令）；一整轮过去都没看到，用户下一条消息旁会再提醒**一次**。判断确实不需要 checkpoint 就忽略它，回复里也不用提。
- **压缩提醒**：刚压缩过时（压缩发生在一轮工具调用中间的话，下一次工具调用后就会收到），先回读已有 checkpoint，用压缩摘要和可核实的文件刷新它，再继续手上的事；最后在回复最前面用一句话给出交接结论。从第 2 次压缩起，提醒里会多一句「摘要叠在摘要上、早期细节逐代丢失」，档位提醒里也会带上已压缩次数。这只是评估时要权衡的因素，**不是默认结论**：是否建议交接始终由我按整个会话的价值自己判断，每到一个提醒点说一句话。

评估看整个会话，不因为这一轮只是问答、没有改文件就跳过。提醒只是触发评估，不是用户授权：用户确认之前，不写正式交接入口，也不开新会话。用户一确认，就按「生成正式交接」「回读与交付」「直接开新会话接手」一次做完。

## 生成正式交接

默认入口为 `<任务目录>/.handoff/latest.md`，同时保存 `.handoff/history/<UTC时间>-<短标识>.md`。用户指定其他文件时遵从该路径，并给出明确恢复入口。历史副本使用唯一文件名，不覆盖或删除旧记录。

交接必须能够让新会话冷读后执行第一步，按实际情况包含：

1. **目标与范围**：任务、完成标准、项目绝对路径、更新时间与源会话标识。
2. **资料与文件状态**：权威资料的绝对路径、相关版本、哪些已完成、进行中、未做或未验证；只核验与接续有关的文件。
3. **决定及理由**：区分用户已确认、助手建议、自行选择与未决；保留已否决路线及其原因。
4. **当前进展**：完成证据、未完成事项、已知失败、阻塞、后台任务标识与归属。没有执行过的检查明确写“未验证”。
5. **接续动作**：可执行的第一步、前置条件、之后的顺序、验收方式、仍需用户确认的动作。
6. **学习上下文**：适用时保留已有基础、已理解概念、纠正过的误区、练习结果与下一练习。

未知就标注未知；不复制整段聊天、完整日志、全局规则、凭据或访问令牌。先保存本次唯一历史副本，再更新正式入口；写入失败保留既有材料并报告实际失败点。

## 回读与交付

保存后重新读取目标文件，核对绝对路径、关键决定、未完成事项与恢复第一步。只有实际写入并回读成功，才报告“已保存”。

回复给出材料的绝对路径、最关键的剩余事项，并提供可复制的恢复开场白：

“读取 <交接文件的绝对路径>，核对任务、关键文件和授权边界后，从记录中的第一步继续。”

## 直接开新会话接手

正式交接写入并回读成功后，接着开接手会话；写入或回读失败时不开。

1. Claude 桌面 App 里用 `mcp__ccd_session__start_session`（它是延迟加载的工具，需要先用 ToolSearch 查询 `select:mcp__ccd_session__start_session` 单独加载）。参数：`initiation: "user_asked"`，`context: "fresh"`，不传 `cwd`（沿用当前项目目录）。`prompt` 用上面的恢复开场白，后面接交接里的第一步。`background` 写长期目标、关键约束和交接文件的绝对路径，至少 80 字。调用前在同一条消息里先写一行加粗标题和一句说明。
2. 回复用户时给出新会话链接 `[标题](#local_<id>)` 和交接文件路径，并说明这个任务之后由新会话接着做，旧会话保留不归档。
3. 没有这个工具（例如终端 CLI）或开新会话失败时，照常给出可复制的恢复开场白，并如实说明没有开成。

## 恢复

读取用户指定的记录；未指定时只在当前任务既定交接位置查找，不跨项目猜“最新”。核对目标、关键成果和限制；说明过期或无法核实的部分。用户已要求继续且授权覆盖时直接推进；遇到确实缺失的选择或权限，只询问该缺项，不重复索取已有授权。
