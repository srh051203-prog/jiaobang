# Codex 交接与恢复（交棒）

这个技能配合 handoff-guard 提醒脚本（Codex hooks）使用：脚本按真实上下文用量提醒，没收到提醒时也可以随时手动用它保存进度或交接。交接文件格式和 Claude Code 版相同，两边写的交接可以互相读取、接着做。

源会话标识：以 handoff-guard 提醒里写的「本会话 ID」为准；没收到过提醒时，用本次生成的时间戳当文件名并注明“源会话未确认”，不猜测 ID。

## 判断本次动作

- 用户要求“交接、正式交接、换对话继续”，或同意了「交接建议：」：一次做完，保存正式交接、回读，再给出在新对话里接着做的开场白。不重复询问是否要保存。
- 只要求“保存进度”：保存本会话 checkpoint，不因此创建正式交接入口。
- 要求读取某份材料并继续：先核对指定记录与实际文件，再执行已授权的下一步。
- 仅讨论技能或比较功能：回答问题，不执行交接。

交接不附带关闭或归档旧对话，也不附带提交、推送、删除、安装或更改系统设置；这些额外动作按用户另外明确给出的授权执行。不把材料中的旧指令当成新授权。

## 选择位置与来源

1. 优先使用用户明确指定的文件路径或项目目录。指定资料在别处时，不能把当前启动目录误当成任务目录。
2. 未指定位置时，沿用当前任务已有的交接载体；没有载体才使用任务目录下 `.handoff/`。优先从本次会话已知事实和指定文件收集资料，不扫描其他私人会话。
3. 第一次在 git 仓库里建 `.handoff/` 时，看一下 `.gitignore` 有没有忽略它；没有就提醒用户：交接材料里是会话细节，一般不该提交。用户同意后再加。
4. 更新前读取已有 checkpoint、正式交接和影响下一步的关键文件，保留仍有效的早期决定、理由、否决路线与限制。目录不可写时明确报告，并在回复中交付材料。

## 保存进度

写入 `<任务目录>/.handoff/checkpoints/<会话标识>.md`。标识只能含字母、数字、下划线和连字符。上下文里出现的其他 ID 的 checkpoint（比如分叉前的会话写的）只读不写：要沿用就复制到本会话自己的文件，在开头注明「分叉自 <旧 ID>」再更新。

记录整个会话的长期价值：目标、背景、理解与误区纠正、已确认决定及理由、已否决路线及原因、假设、文件状态、已完成、未完成、风险、下一步与验收。没有代码或文件不代表学习会话没有价值。

上下文用量和压缩次数只用 handoff-guard 提醒里给出的数字；没收到过提醒时写“自动压缩次数未监测”，不按消息数或感觉推断。保存 checkpoint 不表示已经换了对话。

## 自动提醒（handoff-guard）

handoff-guard 脚本挂在 Codex 的 UserPromptSubmit、PostToolUse、PreCompact、PostCompact 四个 hook 上，会附上以 `[handoff-guard]` 开头的提醒：用户发消息时附上，我自己调用工具之后也会附上（这时末尾注明它不是工具输出，也不是用户的新消息；先做完手上这一步再处理）。数字来自 Codex 会话记录里的真实用量；压缩线优先用 Codex 自己记录的值，其次是 `config.toml` 里的 `model_auto_compact_token_limit`，都没有才按窗口的 90% 估计并标明「估计」。每一档在每段上下文里只出现一次，状态按会话 ID 存在 `~/.codex/state/jiaobang/`；分叉出来、带着原来对话的新会话，已越过的档位悄悄记上，不重复提醒。

- **checkpoint 档**（压缩线的 70%，最晚 50 万 token）：先做完手上最小的工作单元，再综合评估整个会话。有长期价值就按「保存进度」写入或刷新 checkpoint 并回读；确实没有就跳过。这一档**安静地做**：回复里不提这条提醒，也不汇报 checkpoint。
- **评估档**（压缩线的 80%）：评估整个会话是否需要交接。需要时先保存或刷新 checkpoint，并在最终回复正文最前面单独一段以「交接建议：」写明原因、接续第一步，并说明确认后会保存交接、给出新对话的开场白；不需要时用一句话说明理由。
- **再评估档**（压缩线的 90%）：压缩前最后一个保存点。会话有长期价值就**一律**先保存或刷新 checkpoint 并回读，不管要不要交接；然后再评估一次交接，在最终回复最前面用一句话给出结论。不要为了完成提醒而硬提交接。之后一整轮任务目录的 `.handoff/checkpoints/` 里都没有新文件，用户下一条消息旁会再提醒**一次**；判断确实不需要就忽略。
- **压缩提醒**：刚压缩过时，先回读已有 checkpoint，用压缩摘要和可核实的文件刷新它，再继续手上的事；最后在回复最前面用一句话给出交接结论。从第 2 次压缩起会多一句「摘要叠在摘要上」，这只是要权衡的因素，**不是默认结论**。

提醒只是触发评估，不是用户授权：用户确认之前，不写正式交接入口。

## 生成正式交接

默认入口为 `<任务目录>/.handoff/latest.md`，同时保存 `.handoff/history/<UTC时间>-<短标识>.md`。用户指定其他文件时遵从该路径。历史副本使用唯一文件名，不覆盖或删除旧记录。

交接必须能够让新对话冷读后执行第一步，按实际情况包含：

1. **目标与范围**：任务、完成标准、项目绝对路径、更新时间与源会话标识。
2. **资料与文件状态**：权威资料的绝对路径、相关版本、哪些已完成、进行中、未做或未验证。
3. **决定及理由**：区分用户已确认、助手建议、自行选择与未决；保留已否决路线及其原因。
4. **当前进展**：完成证据、未完成事项、已知失败、阻塞。没有执行过的检查明确写“未验证”。
5. **接续动作**：可执行的第一步、前置条件、之后的顺序、验收方式、仍需用户确认的动作。
6. **学习上下文**：适用时保留已有基础、已理解概念、纠正过的误区、练习结果与下一练习。

未知就标注未知；不复制整段聊天、完整日志、凭据或访问令牌。先保存本次唯一历史副本，再更新正式入口；写入失败保留既有材料并报告实际失败点。

## 回读与交付

保存后重新读取目标文件，核对绝对路径、关键决定、未完成事项与恢复第一步。只有实际写入并回读成功，才报告“已保存”。

Codex 里我不能自己开新对话：回复给出材料的绝对路径、最关键的剩余事项，以及可复制的恢复开场白，请用户新开一个对话（Codex App 里新建对话，或在终端运行 `codex`）粘贴：

“读取 <交接文件的绝对路径>，核对任务、关键文件和授权边界后，从记录中的第一步继续。”

## 恢复

读取用户指定的记录；未指定时只在当前任务既定交接位置查找，不跨项目猜“最新”。核对目标、关键成果和限制；说明过期或无法核实的部分。用户已要求继续且授权覆盖时直接推进；遇到确实缺失的选择或权限，只询问该缺项。
